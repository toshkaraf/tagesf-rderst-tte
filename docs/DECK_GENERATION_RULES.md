# Правила генерации тематической презентации с викториной

Эталон: «Кардинал Ришелье» (`tools/richelieu-deck/`, `public/richelieu/index.html`). Руководство по подключению к сайту: `docs/NEW_DECK_GUIDE.md`, квиз-модуль: `tools/common/QUIZ_README.md`.

## 1. Содержание и язык
- Язык слайдов — немецкий, уровень **B1**: короткие предложения (до ~15 слов), простая лексика, термины объясняются сразу, цифры и даты конкретно.
- **30 слайдов** + титульный. Структура: 5 частей (≈ 5–7 слайдов), от «кто/что» к выводу; последний слайд — вывод/вопрос напоследок.
- Слайд: `cat` (КАТЕГОРИЯ заглавными), `title` (до ~8 слов), `text` (2–3 предложения, ≤ 45 слов), `motif` (описание картинки, alt).
- Источник — пост/текст пользователя. Разрешено сокращать, добавлять, править. **Проверять факты** (даты, цифры, цитаты); сомнительное смягчать («по оценкам историков», «sollen … haben»). Реклама/подписи/призывы автора — убрать.
- Тон нейтральный, образовательный, без оценочных вольностей оригинала, если они искажают факты.

## 2. Картинки
- Для слайдов **без видео** — по одной картинке (≈ 23 из 30). На видеослайдах картинки нет (превью ролика).
- Источник — Wikimedia Commons: предпочтительно общественное достояние / CC0; указывать автора/тип + «Wikimedia Commons» на слайде и в заметках. Картины, гравюры, карты, нейтральные фото.
- Подбор через Commons API (`action=query&generator=search`), обязательно заголовок `User-Agent`. Лимиты: скачивать **стандартные миниатюры** (`/thumb/…/960px-…`, для маленьких оригиналов `500px`), по одному файлу, пауза ≥ 12 с и `Retry-After` при HTTP 429; оригиналы больших файлов не качать.
- Если Commons отвечает 429 (лимит на скачивание миниатюр): скачивать по одному с честным User-Agent и Retry-After; запасные источники общественного достояния — The Met Open Access (`collectionapi.metmuseum.org`, `images.metmuseum.org`) и Library of Congress (`www.loc.gov`, `tile.loc.gov`) — хосты добавляются в сетевой список окружения. В подписи на слайде указывать источник («/ The Met, Open Access», «/ Library of Congress»). Оставшиеся картинки записать в `images-pending.json` (см. `tools/sweden-deck/`).
- Обрезка: портрет — сохранять верх (лица), соотношение сторон 0.75–1.5, ширина ≤ 900 px (`prep.py`). Проверить глазами, что картинка соответствует слайду (карты/периоды!).

## 3. Видео
- **7 роликов на 30 слайдов** (каждые 3–5 слайдов), обычно на слайдах-«якорях» темы.
- Критерии: без дикторского текста (музыка) **или** немецкий/английский; **длительность строго ≤ 180 с**; `embeddable=true`; публичное.
- Проверка только по метаданным через YouTube Data API v3: `videos?part=contentDetails,snippet,status` (длительность ISO 8601 → секунды, `defaultAudioLanguage`/`defaultLanguage`, `embeddable`, `privacyStatus`). Поиск кандидатов: `search.list` (`type=video`, `videoDuration=short`, `videoEmbeddable=true`, `relevanceLanguage=de|en`) → затем снова `videos.list`.
- Язык, который API не указывает, оценивать по названию/каналу/описанию и **честно помечать «не подтверждено»**. Содержание роликов не просматривается — это говорить прямо.
- Для каждого ролика: id, название на слайде («Название (Канал)»), превью `https://img.youtube.com/vi/<id>/hqdefault.jpg` → кроп чёрных полос до 480×270 (`ytc_<id>.jpg`). Ключ API нигде не сохранять и не коммитить.
- Итоговая таблица: слайд, ролик, канал, длительность, язык, статус проверки.

## 4. Викторина
- Файл `quiz.json`: группы `{after: <№ слайда>, q: [3 вопроса]}` после каждых 3–4 логически связанных слайдов (≈ 9 групп, **27 вопросов**), вопрос стоит после видеостраницы своего слайда.
- Каждый вопрос: текст (B1) и 4 ответа; **первый ответ в JSON — всегда правильный** (модуль сам расставляет позиции по кругу, а в итоговом тесте перемешивает).
- Вопросы — по фактам со слайдов, без подвохов; неправильные ответы правдоподобные, но разной длины/структуры не выдавать правильный (≈ равная длина).
- Поведение (веб/APK): клик → звук успеха, правильный зелёный на 2 с; неверный выбранный красный + правильный зелёный; через 2 с следующий вопрос/слайд. После всех слайдов — итоговый тест (все вопросы вперемешку, ответы перемешаны) с результатом в %, кнопки «повторить» / «к началу».
- PowerPoint-вариант (`QUIZ=1 node build.cjs`): скрытые слайды-реакции, автопереход 2 с, звук; без случайного порядка и автопроцента (таблица «правильных → %»).

## 5. Стиль (у каждой презентации СВОЙ)
- Не копировать оформление прежних презентаций (роботы: тёмно-синий/оранжевый; Ришелье: бордо `#2A0A12`/`#5A1426`, золото `#C9A227`, крем `#F6EFE3`, Cambria + Calibri). Для новой темы придумать палитру и шрифтовую пару, отвечающую эпохе/смыслу, и свою композицию титула.
- Тема задаётся в `build.cjs` (THEME/master), `gen.cjs` (CSS) и в записи сессии `embedTheme {bg, fg, accent}`; цвета квиза (`QTHEME`) — из той же палитры.

## 5a. Панель управления (для всех презентаций)
- Кнопки перелистывания ◀ ▶ — крупные (≈ 92×76 px, в 2 раза больше обычных), по центру нижней полосы.
- Кнопки «в начало» (⏮) и «на весь экран» (⛶) — маленькие, в левом нижнем углу полосы; ссылка «YouTube» (на видеослайдах) — в правом нижнем углу.
- Образец: `tools/cincinnatus-deck/gen.cjs` (`#bar`, `.nav`, `.corner`).

## 6. Реализация и выдача
1. `tools/<name>-deck/`: `slides.json`, `quiz.json`, `build.cjs` (pptx), `gen.cjs` (веб), `prep.py`, `img/`. Шаблон — `tools/richelieu-deck/`; общий код — `tools/common/`.
2. Сборка: `PPTX_SKILL_DIR=/mnt/skills/public/pptx NODE_PATH=…(pptxgenjs, jszip) node build.cjs`, `node gen.cjs` → `public/<name>/index.html`.
3. Сайт: запись `src/data/<name>-deck-session.ts` (`embedUrl`, `embedTheme`, `created` = сегодня → самая верхняя тема), добавить в `sessions.ts` и DE/RU заголовки в `sessionTranslations.ts`.
4. Проверка: `npm run build`, `vite preview`, Playwright: список `/topics` (новая тема первая), клик, прохождение квиза (2 с, красный/зелёный), итог в %, кнопка «назад».
5. APK (по запросу): WebView-оболочка `android-richelieu/` с новым `index.html`, `gradle assembleDebug` (ANDROID_HOME с platforms;android-34, build-tools;34.0.0).
6. Коммит и push в `main`. Vercel: функции в `api/` имеют `excludeFiles` (бандл ≤ 225 МБ) — тяжёлые файлы только в `public/`.
7. Ответ пользователю: таблица видео, что не подтверждено (честно), ссылки на файлы, что не проверено (звук в реальном PowerPoint/APK и т.п.).
